# English Grammar Lab — 题库数据规范 (DATA_SCHEMA)

本文件是所有 `data/bank-tense-*.js` 题库文件必须严格遵守的契约。请先完整阅读本文件，再阅读你专属的 `spec/brief-tenseNN.md`，然后生成对应题库文件。

---

## 1. 文件格式与注册方式

每个题库文件是一个 IIFE，向全局注册表写入一个 topic 对象：

```js
// data/bank-tense-01.js
(function () {
  "use strict";
  window.__GRAMMAR_LAB__ = window.__GRAMMAR_LAB__ || {};
  window.__GRAMMAR_LAB__.tense01 = { /* ... 见下方 schema ... */ };
})();
```

- `tense01` 是 topic id，必须是你在 brief 中看到的 `tenseNN`（NN=01..12 两位数字）。
- 一个文件只注册**一个** topic。
- 所有代码必须能在旧手机浏览器运行：只使用 ES5/ES6 基础语法（`var`/`function`/对象字面量/字符串/数组），**不要**用箭头函数、模板字符串、解构、`let/const`（防止个别 WebView 老内核报错）。字符串统一用**单引号**。
- 文件编码 UTF-8（无需 BOM）。中文解释用中文书写。

### 文件长度处理（重要）

如果单次写入内容过长，请这样分两次写入：
1. 第一次 `write` 写入文件前半部分（含注册开头 + 前半题目），文件结尾放一行哨兵：
   ```
   /*__MORE__*/
   ```
2. 然后用 `edit` 工具，把 `/*__MORE__*/` 这一行替换成剩余内容（题目后半 + 对象闭合 + `})();`）。edit 时 old_string 写 `/*__MORE__*/`，new_string 写剩余内容。
3. 可重复多次。最后文件中不能残留 `/*__MORE__*/`。

  // —— 知识卡 ——
  knowledgeCard: {
    oneLine: '一句话理解：……',                 // 1-2 句
    structure: '基本结构：……（如需动词三单变化、不规则动词表可在此用中文简单说明）',
    scenes: ['① ……', '② ……', '③ ……', '④ ……'],  // 3-5 条常见场景/标志，每条 8-20 字

  tags: ['第三人称单数', '习惯性动作', '客观事实/规律', '时刻表/固定安排', '时间状语从句中的时态'],

  questions: [ /* 12 个核心题 + 见下方 pool */ ],
  pool: [ /* 5 个扩展输入题（再练5题 / 挑战模式 / 综合挑战使用） */ ]

## 3. 核心题：questions 数组（必须恰好 12 个）

- `questions[0..5]`（第 1-6 题）：`type:'choice'`，六选一。
- `questions[6..11]`（第 7-12 题）：`type:'input'`，自己拼写。

每个 question 对象：

```js
{
  id: 'tense01q01',        // 全库唯一
  pos: 1,                  // 1..12，必须与数组顺序一致
  type: 'choice',          // 'choice' | 'input'
  difficulty: 1,           // 1-5
  tag: '第三人称单数',       // 必须是本 topic tags 数组中的某一个
  wrongType: 'SUBJECT_VERB_AGREEMENT', // 该题答错时最可能犯的错误类型代码（见 §6）
  question: '完整英文句子，空格处写 ______',
  hint: '',                // input 题才需要：括号提示原文，如 'work' 或 'already / leave'；choice 题为空字符串
  options: ['A文本', 'B文本', 'C文本', 'D文本', 'E文本', 'F文本'], // 仅 choice 需要，恰好 6 个
  answerIndex: 1,          // 仅 choice：正确选项下标 0..5
  accepted: [],            // 仅 input：所有可接受的答案变体数组（小写，不含句点），至少 2 个常用变体
  answerText: 'finds',     // 展示用标准答案（大小写规整）
  explanation: {           // 所有字段必填，中文，见 §5
    answer: 'finds',       // 正确答案展示文本
    keyPoint: '考查知识点……',
    clue: '🔎 本题关键线索：……',
    trap: '⚠️ 不要被……骗了 / 哪个信息最关键',
    chain: 'usually ↓ 习惯性动作 ↓ 一般现在时 ↓ 主语Jack为第三人称单数 ↓ finds',
    why: '为什么选这个（判断依据）……',
    whyOthers: 'A. find — 主语是第三人称单数，动词不能裸用；\nB. ……；',
    commonError: '容易犯的错误……',
    memory: '一句话记忆……',
    examMind: '🧠 如果你在考试现场：看到…… 快速想到……',
    cue: '🧠 以后看到什么就想到什么：usually → 习惯 → 一般现在时 → 三单变化',
  }
}
```

**说明：**
- `hint` 会在界面中紧跟在 `______` 后以小括号显示，例如 `He ______ (work) in a radio factory at that time.`。
  所以 question 文本中**不要**再自己写括号提示。hint 需要多个词的用 `/` 分隔（如 `'already / leave'` 表示该空覆盖 already 与 leave 两部分，答题者需填完整动词短语）。
- `accepted`：input 题必须给全合理变体。规则：全部小写写；可含缩写变体（如 `'had left'` 与 `"'d left"` 都写）、完全式与缩写式都写（如 `'does not go'`、`"doesn't go"`、`'doesn t go'` 由程序归一化，但你仍应把 `doesn't` 与 `does not` 两种都列出）；大小写程序会忽略。**不要**把错误形式放进 accepted。
- `options` 中**不要**出现与正确答案完全等价的形式（如答案 has finished，选项里不得再出现 has finished）。

## 4. pool 数组（再练5题 / 挑战模式 的题库）

- **恰好 6 个**，全部 `type:'input'`，与 §3 对象结构一致，但难度更高：
  - `difficulty` 3-5；
  - 句子长度 **15-30 个英文单词**，上下文更复杂，更接近真实高中语法填空；
  - 每个 pool 题的 tag 尽量覆盖本专题不同子知识点（不要 6 个都同一个 tag，至少分散到 4 个以上）。
- id 形如 `tense01p01`…`tense01p06`。
- pool 题解析字段可略简于核心题，但 answer/keyPoint/clue/trap/why/whyOthers/commonError/memory/cue 必须齐全、成段，不能一句话敷衍。
- pool 题的解析同样要完整（字段同 §5），因为它们用于"再练5题/挑战模式"，学生仍会看解析。
- pool 题也必须遵守全部质量规则（§7）。

## 5. explanation 各字段写作要求（每题必填且内容充实）

| 字段 | 写作要求 |
|---|---|
| answer | 标准答案文本 |
| keyPoint | 考查哪个语法知识点，一句话讲清 |
| clue | 🔎 本题关键线索：指出句中**真正决定答案的信息**（词或短语），并说明为什么重要 |
| trap | ⚠️ 易错点 / 不要被什么骗了：指出最可能把学生引向错误答案的干扰信息，并强调哪个信息最关键 |
| chain | 判断链：用 `A ↓ B ↓ C ↓ D` 逐级推理（每步 4-12 字），一般 4-7 步 |
| why | 为什么是这个答案：结合句子成分、时态语义详细解释（2-5 句）。**禁止**只写"因为表示过去所以用过去时"这种一句话解析 |
| whyOthers | 为什么其他答案不合适：choice 题逐项说明（每项 1-2 句）；input 题说明"易错写成 X，为什么不行"（1-3 条） |
| commonError | 学生常见错误与原因（1-3 句） |
| memory | 一句话记忆口诀 |
| examMind | 🧠 如果你在考试现场：看到某个线索快速联想到什么（1-2 句） |
| cue | 🧠 以后看到什么就想到什么：线索→结论链条（可重复 chain 要点，面向记忆） |

所有解析用**面向高一学生的中文**，自然、具体、有教学味道，不要干瘪。

## 6. 错误类型代码 wrongType（必须从下面选）

TIME_SIGNAL_ERROR（时间标志误判）、CONTEXT_ERROR（上下文判断错误）、TENSE_CONFUSION（时态混淆）、VOICE_ERROR（语态错误）、SUBJECT_VERB_AGREEMENT（主谓一致）、VERB_FORM_ERROR（动词形式错误，如该用过去分词用了原形）、SPELLING_ERROR（拼写错误）、WORD_FORM_ERROR（词形词性错误）、PREPOSITION_ERROR、ARTICLE_ERROR、PRONOUN_ERROR、CONJUNCTION_ERROR、CLAUSE_ERROR、COLLOCATION_ERROR。

选"学生答错这道题时，最可能错在哪类"。选择/输入题都填。

## 7. 题目质量硬规则（违反即返工）

R1 **句子长度**：绝大多数核心题句子（含题干，不含选项）≥ 10 个英文单词；综合/上下文题 12-25 词；pool 题 15-30 词。宁长勿短，但不机械堆词。句子必须自然、像高中真实作业。

R2 **必须有上下文/信息量**：禁止 `He went to school yesterday.` 这类"时间词直接泄题"的单薄句。要通过时间状语、原因、转折、条件、并列、从句、对话引语、前后句逻辑自然加长句子，且答案**唯一明确**。

R3 **禁止歧义题**：若句子在标准英语里可有两个都合理的答案，必须改写题干消除歧义，而不是强行判错。
- 禁止 `I ______ (go) to Shanghai next month.`（will go / am going / am going to go 都合理）。
- 涉及将来，请给"已买票/已安排/临时决定"等语境使答案唯一。
- 涉及完成时与过去时，请用 since/for/already/yet/延续性语境 或明确过去时间点使答案唯一。
- 设计完成后自查：把每个选项放回句子读一遍，若有除答案外仍完全通顺合理的选项 → 改写题干或换题。
- 语法上本身允许双表达的（如美式 have got 等）不要用作考点。

R4 **干扰项必须是真实错误**：选项必须来自学生真实会犯的错误（时态误配、主谓不一致、形式错误、完成/过去/进行混淆等）。禁止无厘头、语法上完全不可能的选项。选项彼此要有区分度（通常 2-3 个非常接近正确答案的"陷阱选项"）。

R5 **场景与人物多样化**：全专题避免同质化（不要整章都是 I/He + school）。轮换人物（含第三人称、复数、代词）、场景（学校、家庭、旅行、科技、运动、学习、天气、社会、城市生活、对话语境、短文语篇等）。词汇难度控制在高中合理范围，不生僻词。

R6 **句式多样化**：12 题尽量混合陈述句、对话引语（"…," she said 类 / 直接引语）、两句话上下文、带原因/条件/转折/时间状语从句的复合句、以及 1-2 题小语篇（2-3 句连续）。第 12 题通常做"接近真实作业"的综合语篇题（2-3 句）。

R7 **难度递进（重要）**：按 §3 中 difficulty 与题位安排：
- 1-2 题（difficulty 1）：基础识别，信号明显（如 usually/often + 三单、yesterday + 过去式、already 类）；
- 3-4 题（difficulty 2）：上下文判断（信号词不直给，需推理）；
- 5 题（difficulty 3）：易混淆辨析；
- 6 题（difficulty 4）：综合应用（需综合 2 个以上线索）；
- 7-8 题（difficulty 2）：输入题，信号较明显，但要求真正拼写（拼写/形式即考点）；
- 9 题（difficulty 3）：需要分析上下文；
- 10 题（difficulty 4）：易混淆；
- 11 题（difficulty 4）：综合判断；
- 12 题（difficulty 5）：接近真实上海高中作业（可用 2-3 句小语篇）。
每道题的 difficulty 与内容难度必须匹配 brief 中的专题细化要求。

R8 **每题都训练"判断"而非"关键词匹配"**：信号词只是辅助。第 5、6、9-12 题尤其要设计成需要综合分析"时间 + 完成/未完成 + 进行/非进行 + 与现在是否有关 + 逻辑"才能判断的题。

R9 **答案与填空格式**：question 中恰好一个 `______`（第 12 题若为双空小语篇，则**只允许一个空**，另一个动作在上下文给出，避免多空判分复杂）。input 题的 hint 如 §3 说明。choice 题 question 无 hint。

R10 **句式自然**：句子要符合真实英语使用习惯，可读性高，禁止生硬拼接（如无意义的 and…and…）。

R11 **禁止**：与示例句雷同的句子；成人/不当内容；真实考试原题的整句照搬（可参考风格，自行原创）。

R12 **全库查重意识**：你的句子要尽量独特，避免与其他专题相同句型套换。尤其不要使用本 schema 示例与用户例子中的句子。

## 8. 交付自检清单（写完后逐条检查再结束）

1. 用 `node --check data/bank-tense-NN.js` 能通过语法检查（在项目根目录运行）。
2. 文件以 `(function () {` 开头、`})();` 结尾，无 `/*__MORE__*/` 残留。
3. `questions` 恰好 12 个：0-5 为 choice（恰 6 个 options、answerIndex 有效、question 含 ______ 且不含括号提示）；6-11 为 input（hint 非空、accepted ≥2 个合理变体）。
4. `pool` 恰好 5 个 input 题。
5. pos 与数组顺序一致；id 全 topic 内唯一（q01..q12、p01..p05）。
6. 每个 question 字符串（英文部分）用空格分词 ≥10 个词（pool ≥15 词）；无法达到的少数题（如对话引语极短）最低不得 <8 词，且每题都要自查。
7. explanation 全部字段齐全且充实；tag 在 tags 数组中；wrongType 在 §6 列表中。
8. 把每题（choice：把每个选项代入句子读；input：把每个 accepted 代入读）通读自查歧义，确保**只有标准答案合理**。
9. 不重复别人例句；专题内句子两两不同。
